# Estiba — Fases 1 y 2: comodidad en el visor, aula real, trazados y caminito de círculos

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que el visor sea cómodo (sin elementos pegados a la vista ni parpadeos), que la app funcione en un aula sin internet y se pueda verificar con pruebas automáticas, que el editor trace vías, carriles y caminos con curvas y uniones, y que el alumno se mueva mirando círculos en el piso.

**Architecture:** Se mantiene la arquitectura del prototipo 1 (reductor puro compartido, servidor de salas con WebSocket, vistas de alumno, escritorio, XR y editor). Se agregan a la escena **trazados** (polilíneas en metros con curvas redondeadas) y a los módulos una **posición y giro libres** opcionales. El servidor suma un modo HTTPS para la red local, la lista de participantes y un registro de errores propio.

**Tech Stack:** el del proyecto (TypeScript 5.6, Vite 5.4, three.js 0.169.0, Node 22 + ws 8.18, Vitest 2.1), más `selfsigned@2.4.1` (certificado para el modo aula) y `@playwright/test@1.48.2` (pruebas de punta a punta; instala Chromium).

**Spec:** `docs/auditoria.html` (publicada en https://claude.ai/artifact/ADAkz8WAWEtb24KPTQa2RG, versión 4), secciones 02, 04, 06 y 09 y las fases 1 y 2 de la sección 10. Contexto del diseño original: `docs/estiba-prototipo.html` y `docs/superpowers/plans/2026-10-22-estiba-prototipo.md`.

## Global Constraints

- Las restricciones globales del plan del prototipo 1 siguen vigentes, en particular: español en toda la interfaz; nunca girar la cámara del alumno; todo cambio de posición del alumno con fundido de 0,3 s; elegir con la mirada a los 1,5 s; texto del visor ≥ 40 px equivalentes; WebXR solo en el Quest; versiones exactas de dependencias; commits terminan con `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Nada de lo nuevo puede depender de servicios pagos ni de internet en el aula.
- Compatibilidad: una sala guardada en `data/` con el formato anterior (sin `trazados`, sin `pos`/`giro` en módulos, sin `recorridoLibre`) tiene que seguir abriendo.
- Caminito: círculos cada **7 m**, visibles a **≤ 25 m**, mirada de **1,5 s**, fundido de **0,3 s**, altura de ojos **1,7 m**. «Recorrido libre» **apagado por defecto** (lo enciende el docente).
- Trazados: radio mínimo de curva **vía 80 m**, **carril 8 m**, **camino 0** (sin redondeo); imán de unión a **3 m**; ancho de carril **3,5 m**.
- Editor: imán a la grilla de **1 m** (con `Shift`, 0,1 m); `Q`/`E` giran ±15°; `R` sigue girando 90°; `Ctrl+Z` deshace; `Ctrl+D` duplica.
- Cámaras: plano cercano **0,5 m**, lejano **1500 m** en alumno y escritorio.

## Review Focus

- Una sala guardada con el formato viejo abre sin errores y se ve igual (test en Task 9).
- Un trazado con puntos repetidos, de un solo punto o con un giro de 180° no rompe el muestreo ni el render (tests en Task 10).
- El alumno se movió por el caminito y el docente cambia de paso o usa «Traer a todos acá»: el alumno vuelve al lugar del paso con fundido (test en Task 14).
- Mensajes nuevos malformados (estado de dispositivo, comandos de trazado, recorrido libre) se ignoran sin tirar el servidor (tests en Tasks 6 y 9).
- El registro de errores no se puede usar para llenar el disco ni leer sin PIN (tests en Task 8).

```ts
// tipos.ts
export type TipoTrazado = 'via' | 'carril' | 'camino';
export interface Trazado { id: string; tipo: TipoTrazado; puntos: [number, number][]; nombre?: string } // puntos x,z en metros

export interface Escena { /* … */ trazados?: Trazado[] }
export interface EstadoSala { /* … */ recorridoLibre?: boolean }
// sala.ts
export type OpEscena = /* … */
  | { op: 'mover'; id: string; celda?: [number, number]; pos?: [number, number] }
  | { op: 'girar'; id: string; grados?: number }        // sin grados: +90 como hasta ahora
  | { op: 'agregarTrazado'; trazado: Trazado } | { op: 'editarTrazado'; id: string; puntos: [number, number][] }
  | { op: 'borrarTrazado'; id: string } | { op: 'restaurar'; escena: Escena };
export type Comando = /* … */ | { t: 'recorridoLibre'; activo: boolean };
// grilla.ts
export function posicionModulo(m: Modulo, metrosPorCelda: number): { x: number; z: number; rad: number };
```
Reglas: `posicionModulo` usa `pos` si existe (si no `celda × m`) y `giro` si existe (si no `rot`), en radianes; `girar` con `grados` suma y normaliza a [0, 360); `mover` con `pos` borra `celda`-dependencia (guarda `pos`); `agregarTrazado` con id repetido o con menos de 2 puntos no hace nada; `editarTrazado` con < 2 puntos no hace nada; `restaurar` reemplaza `escena` completa (se usa para deshacer) y limpia `resaltado` si el módulo ya no existe; `recorridoLibre` cambia el estado (sin efecto si ya tiene ese valor). `estadoInicial` deja `recorridoLibre: false`. La validación del protocolo acepta todo lo anterior con tipos estrictos (puntos finitos, máximo 500 puntos por trazado, máximo 200 trazados por escena, `restaurar` con la misma validación de escena que se usa al cargar).
Todos los consumidores de `celda × metrosPorCelda` y `rot` (EscenaViva, animaciones.ts `origen`/`local`/`moverTractor`/`volverModulo`, editor y `rectanguloHuella`) pasan a usar `posicionModulo`.
